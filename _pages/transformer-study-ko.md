**시작: 2026.02 · 역할: 자료 제작 총괄**

## 논문을 읽는 데서 직접 구현하는 데까지

A.ing 주니어 트랙에서 Transformer의 개념과 코드를 연결해 이해할 수 있는 스터디 자료 제작을 총괄했습니다. 목표는 모델을 가져다 사용하는 데서 한 걸음 더 나아가, 각 연산이 왜 필요하고 코드에서는 어떻게 구현되는지 설명할 수 있도록 돕는 것이었습니다.

처음 Transformer를 공부할 때는 논문의 수식이 코드의 어느 부분에 해당하는지 찾기 어렵습니다. 구조 그림을 이해해도 직접 구현하려면 연산 순서와 Tensor의 차원을 다시 짚어야 합니다. 이런 어려움을 줄이기 위해 배경지식 확인, 논문 읽기, 직접 구현, 비교 실험 순으로 자료를 만들었습니다.

## 개념 설명과 구현 코드를 연결

개념을 요약한 치트시트, PyTorch 사용법을 설명하는 쿡북, 실습 노트북, 퀴즈는 각각 역할이 다릅니다. 하지만 모든 자료가 논문만 참조하면 학습자는 특정 개념이 어느 코드에 해당하는지 직접 찾아야 합니다. 자료를 더 만드는 것만으로는 이 문제가 해결되지 않았습니다.

논문 가이드를 중심으로 각 자료의 대응 관계를 연결했습니다. 가이드의 R01~R13 항목마다 논문 위치와 질문, 해석, 관련 자료의 위치를 모았고, 치트시트와 쿡북, 노트북, 퀴즈에서도 해당 가이드를 찾아갈 수 있도록 구성했습니다.

예를 들어 Multi-Head Attention을 공부할 때는 논문과 치트시트에서 개념을 확인하고, 쿡북에서 Tensor를 각 head로 나눴다가 합치는 코드를 살펴본 뒤 관련 빈칸을 구현할 수 있습니다. 구현 중 막히면 해당 설명을 다시 찾아볼 수 있도록 링크를 달았습니다.

논문을 읽는 순서와 구현 순서도 구분했습니다. 논문에서는 Attention 뒤에 나오는 입력 Embedding과 위치 정보를, 구현할 때는 먼저 살펴보도록 안내했습니다. 논문 목차를 그대로 따르기보다 현재 학습 단계에 필요한 내용을 찾을 수 있게 했습니다.

## Tensor의 shape와 Masking을 단계별로 확인

Attention 수식을 알아도 Tensor 연산을 직접 작성하려면 각 차원이 무엇을 나타내는지 구분해야 합니다. Batch, 문장 길이, head 수, feature 차원을 짚고, Self-Attention과 Cross-Attention에서 입력 길이가 어떻게 다른지도 확인해야 합니다. Mask는 shape가 맞아도 허용할 위치와 차단할 위치를 반대로 처리하면 잘못된 결과가 나옵니다.

실습 노트북은 완성된 코드를 읽는 대신 36개 빈칸을 직접 채우도록 구성했습니다. 각 단계에는 입력과 출력 차원을 확인하고 값이 유한한지 검사하는 코드 등을 넣었습니다. Cross-Attention의 길이와 Padding 처리처럼 단순한 출력 모양만으로 확인하기 어려운 부분도 별도 검사로 다뤘습니다.

오류가 났을 때는 정답만 보여주는 대신 어떤 빈칸과 쿡북 항목을 다시 봐야 하는지 안내하도록 했습니다. 쿡북에도 API 이름만 나열하지 않고 입력 차원, 연산, 출력 차원과 흔히 혼동하는 부분을 함께 설명했습니다.

학습자가 자신이 작성한 연산을 검사하고, 잘못된 부분은 관련 설명을 다시 읽으며 수정할 수 있도록 했습니다.

## 모델 학습 없이 실행하는 비교 실험

처음부터 번역 데이터를 준비하고 모델을 학습시키면 실행 환경과 계산 자원이 개념 학습의 진입장벽이 될 수 있습니다. 학습이 정상적으로 끝나더라도 점수 하나만으로는 개별 설계의 역할을 이해하기 어렵습니다.

그래서 데이터 다운로드나 모델 학습 없이 실행할 수 있는 작은 비교 실험을 마련했습니다.

| 실험 | 비교하는 내용 | 학습자가 살펴볼 점 |
|---|---|---|
| Scaling | head 차원에 따른 Scaling 전후의 점수 분산과 softmax 분포 | Dot Product에 Scaling을 적용하는 이유 |
| 위치 정보 | 위치 정보 유무에 따라 입력 순서를 바꿨을 때의 Encoder 출력 비교 | Attention에 위치 정보가 필요한 이유 |

번역 모델을 학습하기 전에 각 연산이 어떤 역할을 하는지 살펴보는 실험입니다. 조건을 바꾸면서 출력이 어떻게 달라지는지 직접 확인하도록 했습니다.

## 같은 조건에서 비교하는 Multi30k 번역 실습

이후 Multi30k 번역 실습에서는 학습자가 구조와 학습 설정을 바꿔보도록 했습니다. 다만 데이터와 평가 방식까지 함께 달라지면 결과 차이가 모델 변경 때문인지 다른 조건 때문인지 판단하기 어렵습니다.

리그전 노트북에서는 공통으로 유지하는 FIXED 항목과 변경할 수 있는 TUNE 항목을 구분했습니다. 데이터 분할과 평가 규칙 등은 유지하고, 허용된 모델 구조와 학습 설정을 조정하도록 구성했습니다. Validation으로 학습 중 모델을 선택하고, 최종 Test 평가와 구분하는 흐름도 포함했습니다.

실습의 목적은 가장 높은 점수를 얻는 데만 있지 않았습니다. 무엇을 바꿨고 그 변화가 결과에 어떤 영향을 주었는지 설명하는 데까지 이어지도록 했습니다.

## 제작 결과

선수자료, 논문 가이드, 치트시트, PyTorch 쿡북, 빈칸·정답 노트북, 퀴즈와 답안, 번역 실습 노트북을 연결한 학습 자료를 제작했습니다.

전체 흐름은 다음과 같습니다.

**배경지식 확인 → 논문과 개념 연결 → 빈칸 구현 → 단계별 동작 확인 → 작은 비교 실험 → 번역 실습과 결과 해석**

각 자료에서 다음에 볼 설명이나 실습을 안내하고, 어려운 부분은 앞선 자료로 돌아가 확인할 수 있게 했습니다.

## 배운 점

익숙하게 사용하던 `reshape`나 Masking도 학습 자료로 설명하려니 다시 확인할 부분이 많았습니다. 각 축이 무엇을 나타내는지, 어떤 조건에서 연산을 적용하는지, 잘못 적용하면 무엇이 달라지는지까지 짚어야 했습니다.

자료를 만들면서 저도 수식과 코드의 관계를 더 꼼꼼히 이해하게 됐습니다. 처음 배우는 사람을 돕기 위해서는 설명을 쉽게 쓰는 것뿐 아니라, 직접 구현해 보고 잘못된 부분을 찾을 수 있는 예제와 검사도 필요하다는 점을 배웠습니다.
